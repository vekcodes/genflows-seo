For the website developer only. Every item below is a change to the HubSpot theme, a template, a page setting, or a portal setting on www.genflows.com. Nothing here needs Search Console, ad accounts, or content writing — that work is in the companion document GenFlows_Marketing_Actions_2026-07-27.

Date: 27 July 2026  ·  Property: www.genflows.com (HubSpot CMS, portal 49399880, theme genflows-theme, blog ID 215071510044)  ·  Supersedes: GenFlows_Website_Dev_Actions_2026-07-22

How this document was produced. Every finding was measured on 27 July 2026 against the live site (rendered HTML of the homepage, the blog listing and a representative post, plus robots.txt, sitemap.xml, response headers) and against the live HubSpot CMS API. Counts and quotes are what the site actually served — not assumptions. Where something needs confirming inside HubSpot (which I have no theme access to), the item is tagged VERIFY.

The one change that matters most: every page on genflows.com loads https://cdn.tailwindcss.com — a 407 KB render-blocking JavaScript compiler that generates the CSS in the browser at runtime. That single line is almost certainly the biggest Core Web Vitals problem on the site, and replacing it with a compiled stylesheet is item D1.

D1 · Replace the Tailwind Play CDN with a compiled stylesheet P0

Measured: <script src="https://cdn.tailwindcss.com"></script> is present on /, /blog and every blog post. The file is 407,279 bytes of JavaScript. It is followed by an inline tailwind.config = {…} block. This is Tailwind's "Play CDN", which Tailwind's own docs state is for prototyping and not for production: the browser downloads the compiler, parses the DOM, generates CSS and injects it — after first paint. That produces exactly the LCP/CLS/INP damage the audit flagged, and no amount of image or font tuning will compensate for it.
Where Theme base layout <head> (the partial included by every template in genflows-theme) + a new build step in the theme source.
Change Compile Tailwind once at build time, ship one small CSS file, delete the CDN script and the inline config.
# 1. Pull the theme locally (HubSpot CLI)
hs fetch genflows-theme ./genflows-theme

# 2. Add the toolchain
npm init -y && npm i -D tailwindcss@3 postcss autoprefixer cssnano

# 3. tailwind.config.js — paste the theme.extend block that is currently inline
#    in the base layout head (colors ink/flame/paper/cloud/smoke/steel/space/
#    graphite, fontFamily Manrope, letterSpacing, boxShadow ink/ink-lg,
#    transitionTimingFunction spring) VERBATIM, then set:
module.exports = {
  content: ['./genflows-theme/**/*.html', './genflows-theme/**/*.hubl.html',
            './genflows-theme/**/*.js', './genflows-theme/modules/**/*'],
  safelist: [ /* any class assembled in HubL, e.g. 'bg-' ~ colour — see note */ ],
  theme: { extend: { /* …existing config… */ } },
}

# 4. Build
npx tailwindcss -i ./src/tailwind.css -o ./genflows-theme/css/main.css --minify

# 5. Upload
hs upload ./genflows-theme genflows-theme

Then in the base layout <head>:

- <script src="https://cdn.tailwindcss.com"></script>
- <script>tailwind.config = { theme: { extend: { … } } }</script>
+ {{ require_css(get_asset_url('../css/main.css')) }}
Watch out Tailwind's scanner only sees class names that appear literally in the source. Any class built by HubL string concatenation (e.g. class="bg-{{ module.colour }}") must go in safelist, or those styles vanish after the switch. Grep the theme for class="[^"]*{{ before shipping and safelist what you find.
While here Two further render-blocking requests in the same head: the Google Fonts stylesheet (Manrope, 6 weights) and the third-party scripts static.claydar.com/init.v1.js and the GA4 loaders. Reduce the font to the weights actually used, add <link rel="preload" as="font" crossorigin> for the primary weight (or self-host the woff2 in the theme), and load Claydar with defer. There is currently no rel=preload anywhere on the site.
Verify View source on a post: no cdn.tailwindcss.com, one main.css link. Run PageSpeed Insights (mobile) on / and on one post before and after and keep both reports — the delta is the proof. Visually diff homepage, blog listing, a post and /consultancy/wouter at 375px, 768px and 1440px.

D4 · HubSpot's editor markup is leaking into schema, share links and titles P0

Measured on /blog/n8n-vs-make-vs-zapier-gtm-automation-2026. The template outputs {{ content.name }} raw, so the inline-editing wrapper HubSpot wraps around it ends up inside JSON-LD and inside a share URL: 
"headline": "<span id=\"hs_cos_wrapper_name\" class=\"hs_cos_wrapper …\">n8n vs Make vs Zapier (2026): The GTM Automation Buyer's Guide</span>"
The same string appears in BreadcrumbList position 3, and the X/Twitter share link's text= parameter is a URL-encoded <span …> tag. Consequence: the headline and breadcrumb values Google reads are invalid, and anyone sharing a post to X posts raw HTML. Also in the same JSON-LD block: "image": [""], publisher.logo.url: "", and a hard-coded "wordCount": 2000 on a ~3,000-word post.
Where Blog post template <head> (the custom JSON-LD block) and the social-share module in the post footer.
Change Set one clean variable at the top of the template and use it everywhere except the visible <h1> (which should keep {{ content.name }} so inline editing still works).
{# top of the blog post template #}
{% set clean_title = content.name|striptags %}

{# JSON-LD — escape for JSON, never interpolate raw #}
"headline": "{{ clean_title|escapejson }}",

{# share links — URL-encode #}
https://twitter.com/intent/tweet?url={{ content.absolute_url|urlencode }}&text={{ clean_title|urlencode }}
https://www.linkedin.com/sharing/share-offsite/?url={{ content.absolute_url|urlencode }}

And never emit empty values — omit the key instead:

- "image": [""],
- "logo": { "@type": "ImageObject", "url": "" }
- "wordCount": 2000
+ {% if content.featured_image %}"image": ["{{ content.featured_image }}"],{% endif %}
+ "logo": { "@type": "ImageObject", "url": "{{ logo_url }}", "width": 512, "height": 512 }
+ {# drop wordCount, or compute it — a wrong value is worse than none #}
Watch out escapejson is the Jinjava filter name; if the template errors, HubL also accepts escape_json. Preview the template before publishing.
Verify Paste a post URL into Google's Rich Results Test: headline and the breadcrumb name are plain text with no <span>, and no property has an empty value. Click the X share button and confirm the pre-filled text is the plain title.

D5 · Never emit an empty og:image — add a branded fallback P0

Measured: the post serves <meta property="og:image" content=""> and <meta name="twitter:image" content="">. The homepage emits no og:image at all. Via the API, 67 of 71 posts have no featured image. Result: every share on LinkedIn, X, Slack and every AI-generated card renders blank.
Where Blog post template head, blog listing template head, site page template head.
Change Produce one branded 1200×630 PNG (logo + wordmark on the ink background), upload to the theme as images/og-default.png, then:
{% set og_image = content.featured_image
                  or get_asset_url('../images/og-default.png') %}
<meta property="og:image" content="{{ og_image }}">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta property="og:image:alt" content="{{ clean_title|escape }}">
<meta name="twitter:image" content="{{ og_image }}">
Note This is the safety net, not the goal — real per-post featured images are better and are being backfilled separately (marketing item M4, which needs the files scope). Build the fallback anyway: it fixes all 67 posts in one deploy and keeps covering future posts that ship without an image.
Verify LinkedIn Post Inspector and the X Card Validator on one post with a featured image and one without — both must render an image card.

D9 · Remove the duplicate GA4 tag P1

Measured: the page loads googletagmanager.com/gtag/js?id=G-P2W608VV8P twice — once from HubSpot's GA4 integration (with Consent Mode v2 wiring) and once from a hand-added gtag() snippet, both calling gtag('config', 'G-P2W608VV8P'). Every visit is counted twice, which inflates sessions and halves reported bounce/conversion rates, and it costs an extra request on every page.

D10 · Image performance: dimensions, lazy-loading, priority, formats P1

Measured: homepage — 30 <img> tags, none with width/height, 25 with loading="lazy". Blog post — 5 <img>, zero lazy, zero dimensions. No decoding, no fetchpriority, no srcset, no rel=preload anywhere on the site. Missing intrinsic dimensions is a direct CLS cause; the blog post's badge images load eagerly even though they sit in the footer.
Where Every template and module that outputs an <img> in genflows-theme (header logo, hero, client logos, partner badges, blog cards, footer).
Change Standardise on this shape:
{# above the fold / LCP element — eager and prioritised #}
<img src="{{ src }}" width="1200" height="630" alt="…"
     fetchpriority="high" decoding="async">

{# everything below the fold #}
<img src="{{ src }}" width="240" height="80" alt="…"
     loading="lazy" decoding="async">
  • Give every image explicit width and height (the real intrinsic pixel size; CSS keeps controlling display size).
  • Make sure the LCP element — the homepage hero — is not lazy-loaded and carries fetchpriority="high". Check which of the 25 lazy images is in the first viewport and un-lazy it.
  • Add loading="lazy" to the blog post's partner badges and any in-body images.
  • Serve responsive, modern formats through HubSpot's own helpers rather than raw <img>: 
    {% set img = resize_image_url(src, 1200) %}
<img src="{{ img }}"
     srcset="{{ resize_image_url(src, 600) }} 600w,
             {{ resize_image_url(src, 1200) }} 1200w"
     sizes="(max-width: 768px) 100vw, 1200px"
     width="1200" height="630" alt="…" loading="lazy" decoding="async">
  • Convert the PNG logos and badges to WebP; the three badge PNGs are decorative and currently full-size.
Verify PageSpeed Insights mobile on / and one post: CLS < 0.1, LCP < 2.5 s, and the "Image elements do not have explicit width and height" / "Properly size images" audits pass. Do this after D1 — the Tailwind CDN currently dominates the numbers.

{% endif %}
