TL;DR

  • Clay has a native Instantly integration with three actions: Find Leads, Verify Email and Add Lead to Campaign.
  • Use an Instantly API v2 key. Clay’s docs say v1 is being sunset.
  • The native Add Lead action is thin. Clay’s University page lists three inputs: Campaign ID, email and a skip-if-in-workspace checkbox.
  • For AI first lines and custom variables, use Clay’s HTTP API column against POST /api/v2/leads, which accepts custom_variables and a personalization string.
  • Clay cannot create the campaign. Build and test it in Instantly first, then paste its campaign ID into Clay.
  • Verify and dedupe before the push, not after. Bad rows in a live campaign cost you sender reputation.

Clay builds the list and the personalization. Instantly does the sending. Between them sits one small step that decides whether your campaign launches clean or burns a fresh domain: how rows get from a Clay table into an Instantly campaign.

We have already covered the Clay to Smartlead handoff. This is the Instantly version, including the part most guides skip: the native action only passes the basics, so personalization needs a different route.

Sourcing note: action names, inputs and auth come from Clay’s University docs and Instantly’s developer docs, read in October 2026. Clay’s action catalog page and its University page disagree on which fields the native action maps, so we treat extra field mapping as unconfirmed and mark it (directional).

The Short Answer

If you only need to drop verified emails into a running campaign, use the native Add Lead to Campaign action. If your campaign uses AI-written first lines or other per-lead variables, call Instantly’s API from Clay’s HTTP API column so those values travel with the lead. Either way, create the campaign in Instantly first.

Setup, Step by Step

1. Build the campaign in Instantly first

The action needs an existing Campaign ID, and Clay offers no create-campaign action. Write the sequence, attach sending accounts, and leave it ready to receive leads. If you are still deciding on mailbox counts, see how many domains and mailboxes cold email needs.

2. Connect with a v2 API key

In Clay, add the Instantly enrichment, choose + Add account and paste an Instantly v2 API key. Per Clay’s docs, v1 is being sunset. If you already have older Find Leads or Add Lead columns, create a new column rather than duplicating the old one.

3. Verify before you push

Do not let unverified addresses reach a live campaign. Run your waterfall enrichment, then a verification step (see email verification tools compared), and add a formula column that is true only when the email is verified and the row passed your ICP filter. Use it in the action’s “Only run if” setting.

4. Turn on the dedupe checkbox

Tick “Skip if Lead is in Workspace”. It skips leads already sitting in any campaign in your workspace, which protects you from emailing the same person from two campaigns.

5. Test on five rows

Auto-update runs on new rows. Build with it off, push five rows, check them in Instantly, then switch it on.

Warning: a campaign that is active while Clay pushes will start sending to the first rows immediately. Keep it paused until the test rows look right.

Passing AI First Lines and Custom Variables

Instantly’s create-lead endpoint, POST /api/v2/leads with Bearer auth, accepts email, first_name, last_name, company_name, website, job_title, phone, a campaign UUID, a personalization string and a custom_variables object. Three details save debugging time:

  • The field is campaign, not campaign_id, and when it is set, email is required.
  • Custom variable values must be string, number, boolean or null. No nested objects or arrays, so flatten anything you build in Clay.
  • Unknown fields are rejected, so a typo in a key fails the request rather than being ignored.

The API also has three skip flags, skip_if_in_workspace, skip_if_in_campaign and skip_if_in_list, and a verify_leads_on_import option. Instantly says the campaign is updated with the custom variables you send. Some third-party notes claim variables must already exist on the campaign, so test one row and confirm the variable renders in the email preview before you push a list (directional). Check Instantly’s help center for the exact variable syntax in your sequence.

Limits, Cost and Plan Gating

  • Rate limits: Instantly’s changelog reportedly raised API limits to about 100 requests per second and 6,000 per minute in March 2026 (directional; seen as a snippet). Push in modest batches regardless.
  • Instantly plans: the pricing page shows Growth, Hypergrowth and Light Speed with different uploaded-contact and monthly-email caps. The page lists an “API, webhooks, and integrations” row but its per-plan marks did not render for us, so confirm API access on your plan. Our Instantly pricing breakdown has the plan detail.
  • Contact caps matter: pushing more leads than your plan’s uploaded-contact limit allows is a common surprise, so size the push to the plan.

Common Mistakes

  • Pushing before verifying. Bounces on a new domain damage reputation fast; monitor with our deliverability monitoring guide.
  • Using a v1 key. It is being sunset and will break the column.
  • Pasting the wrong ID. Campaign ID is not the campaign name; copy it from Instantly.
  • Sending nested JSON in custom variables. Flatten it first.
  • Letting auto-update run on a half-built table.

Frequently Asked Questions

Does Clay have a native Instantly integration?

Yes. Clay offers three Instantly actions: Find Leads, Verify Email and Add Lead to Campaign.

Which Instantly API key should I use with Clay?

Use a version 2 key. Clay’s docs say the v1 API is being sunset.

Can Clay create an Instantly campaign?

No. The Add Lead to Campaign action needs an existing Campaign ID, and Clay’s docs list no create-campaign action. Build the campaign in Instantly first.

How do I avoid duplicate leads between campaigns?

Tick “Skip if Lead is in Workspace” in the native action. Through the API you can instead use skip_if_in_campaign, skip_if_in_list or skip_if_in_workspace.

How do I pass an AI-written first line from Clay to Instantly?

Use Clay’s HTTP API column to call POST /api/v2/leads and send the line as personalization or inside custom_variables, then reference it in your Instantly sequence. Test one row first to confirm it renders.

Are there rate limits when pushing from Clay to Instantly?

Yes. Instantly’s changelog reportedly puts the limit near 6,000 requests per minute, but that came from a secondary snippet, so push in moderate batches and watch for errors.
