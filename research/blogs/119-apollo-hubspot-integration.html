TL;DR

  • Apollo has two HubSpot integrations. “HubSpot CRM” is a two-way sync. “HubSpot Data Enrichment” only enriches existing records (directional).
  • Set sync rules before you push anything. Push conditions, field mapping and overwrite behavior decide what lands in HubSpot and what gets replaced.
  • Protect good data with auto-fill. Overwrite replaces existing HubSpot values, and manual pushes ignore both rules.
  • Most failed syncs are mapping problems: read-only properties, mismatched dropdowns, multi-checkbox fields and unmapped phone types.
  • Apollo does not document some details we would want: the required plan tiers, the pull interval and rate limits. Test in a sandbox first.

Apollo is where many teams find leads and run first-touch sequences. HubSpot is where the pipeline, reporting and handoffs live. If the two are connected carelessly, reps overwrite each other’s data and nobody trusts the funnel report. If they are connected on purpose, every reply and meeting shows up where deals are managed.

The Short Answer

Connect HubSpot from Apollo’s Integrations page as a HubSpot super admin, choose the CRM integration rather than data enrichment, and configure sync settings and field mapping before the first push. Use push conditions to send only qualified net-new contacts, set sensitive fields to auto-fill so Apollo never overwrites reps’ edits, and map stages one-to-one.

Step-by-Step Setup

  1. Check permissions. You need to be a HubSpot super admin, plus have CRM edit permission or admin rights in Apollo (directional).
  2. Disconnect any other CRM. Apollo supports one connected CRM at a time (directional).
  3. Connect. In Apollo go to Integrations, click Connect next to HubSpot, sign in, choose the HubSpot account and click Connect app. The flow looks like OAuth, but the docs we saw never use that word.
  4. Decide who owns the connection. Team sync lets one user be the primary connection under Settings > Integrations > HubSpot > Authentication (directional). Record ownership on push depends on whether the pushing user connected personal credentials or the team connection falls back.
  5. Configure sync settings and mapping inside the setup window. Apollo says paid plans get a 6-hour window after enabling to configure everything, during which manual pulls are blocked (directional).
  6. Backfill if needed. Mappings only apply to records created or updated after you save, so use Push all or Pull all for existing data (directional).
Not documented in what we could read: which Apollo plan tier unlocks CRM sync, which HubSpot tier is required, the pull interval, and any record caps or API rate limits. Do not promise a client any of these until you have checked your own accounts.

Push conditions: send fewer, better contacts

Push conditions live under Edit Conditions on the Contacts, Accounts, Deals and Activities sync tabs. Options include pushing all new contacts or filtering by stage, email verification status or a custom field (directional). For outbound, the safest default is pushing only contacts that reach a meaningful stage, such as replied or interested, instead of every prospect you save. Otherwise HubSpot fills with cold records that inflate your contact count and distort reporting. If you use an email-status filter, contacts without an email will not sync.

Auto-fill vs overwrite

Auto-fill writes only into empty HubSpot fields. Overwrite replaces existing values when Apollo has different data. One summary says overwrite is the default for mapped fields, but Apollo describes the setting in two places with different labels, so check the live UI (directional). Our recommendation: use auto-fill for job title, phone and anything reps edit by hand, and reserve overwrite for fields Apollo should own, such as employee count or industry. Remember that a manual push ignores both rules, so train reps on that before they use it.

Activity sync

Emails, tasks, notes, conversations and calls are configured separately. Only completed tasks push, activity pushes are delayed by at least 10 minutes, and an activity needs its parent record to exist in HubSpot first (directional). That last rule is why a restrictive push condition can leave you with replies that never appear on a HubSpot timeline.

Stages, Lifecycle and Ownership

You can map HubSpot Lifecycle stage or Lead status to Apollo stages (directional). The mapping must be one-to-one: mapping one HubSpot status to several Apollo stages breaks the sync. If anyone renames, adds or deletes a HubSpot stage, update the Apollo mapping and run Push all or Pull all. Our HubSpot deal stages guide for outbound teams covers designing the stages themselves.

Apollo sequence stage triggers can move a contact’s stage when an email is delivered or a reply comes in, and by default contacts in the Replied, Interested, Do Not Contact and Bad Data stages are excluded from sequence sends (directional). Combining a reply trigger with a push-by-stage condition is a sensible way to get replies into HubSpot, but no Apollo page we saw states that pairing explicitly, so test it. Owner changes in HubSpot reach Apollo only if the sync user’s permission profile allows assigning contact owners (directional). Pair this with fast lead routing so a positive reply reaches a human quickly.

Duplicates and Data Hygiene

HubSpot allows one contact per email address. If a contact already exists, Apollo skips creating a duplicate and logs the event in the integration error log (directional). Companies behave differently: Apollo mirrors HubSpot duplicates and does not auto-merge them. Merge and deletion sync settings can carry HubSpot merges and deletions into Apollo. Clean duplicate companies in HubSpot before the first big push; our CRM data hygiene guide has a checklist.

Frequently Asked Questions

Can I connect Apollo to HubSpot and Salesforce at the same time?

No. Apollo’s help center says only one CRM can be connected at a time, so disconnect Salesforce before connecting HubSpot (directional).

Who can set up the Apollo HubSpot integration?

A HubSpot super admin who also has CRM edit permission or admin rights in Apollo (directional). Confirm the exact requirement on Apollo’s current setup article.

Will Apollo overwrite my existing HubSpot data?

It can. Mapped fields use an auto-fill rule (empty fields only) or an overwrite rule, and manual pushes ignore both (directional). Set protected fields to auto-fill before you turn on sync.

Does Apollo create duplicate contacts in HubSpot?

HubSpot allows one contact per email address, so Apollo skips the duplicate and logs it in the integration error log (directional). Companies are different: Apollo mirrors HubSpot duplicates rather than merging them.

Are Apollo emails and calls logged in HubSpot?

Yes if you enable them. Activity settings cover emails, tasks, notes, conversations and calls separately, and pushes are delayed at least 10 minutes (directional). The contact must exist in HubSpot first.

Why did my Apollo push to HubSpot fail?

The usual causes are read-only HubSpot properties, dropdown values that do not match, multi-checkbox fields, unmapped phone types and stale mappings. Check Error logs under the HubSpot integration settings.
