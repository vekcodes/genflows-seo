OutboundSync: What It Does

OutboundSync's page describes a near-real-time log of HeyReach activity as Close lead activity. It lists eight activity types: connection requests sent and accepted, messages and replies, follows, post likes, profile views and tag updates, including auto-tags.

  • Setup: a Close admin authorises the integration through the Close App Marketplace, you add your HeyReach API key, confirm contact matching, test with one event, then go live.
  • Direction: one-way, HeyReach to Close. The page labels the pairing beta.
  • Objects: it "matches or creates" Close leads. There are no prebuilt Smart Views, but you can build your own from the synced tag data.
  • Plans: the page says webhooks and the API are included on all HeyReach plans.
  • Limit: Close records cannot be used as a block list. That option is available only for HubSpot lists or Salesforce reports.
Check the billing model. OutboundSync bills on its own basis (sent messages per month, per its page), on top of HeyReach and Close. Price it before you commit. See our HeyReach pricing guide and Close CRM pricing guide for the other two line items.

The DIY Route: HeyReach Webhooks

HeyReach lets you subscribe to events and receive an HTTP POST at an endpoint you choose. According to OutboundSync's HeyReach webhook guide, the useful events are: Connection Request Sent, Connection Request Accepted, Message Sent, Inmail Sent, Every Message Reply Received, Follow Sent, Liked Post, Viewed Profile, and the tag events (Lead Tag Updated and the auto-tag variants). The same guide suggests skipping campaign lifecycle events.

For most teams, three events are enough: Connection Request Accepted (a warm signal), Every Message Reply Received (the one reps must act on), and Lead Tag Updated (sentiment or status). Logging every profile view and like in the CRM adds noise without helping a rep decide what to do next.

We could not read HeyReach's own payload documentation, so check the exact field names in your account's test event before mapping. Pick your middleware using our n8n vs Make vs Zapier comparison.

Mapping LinkedIn Prospects to Close's Data Model

Close's developer docs describe a lead as a company or organisation that can hold contacts, tasks, opportunities and activities. A contact is an individual person and must be a child of a lead. Custom fields can be stored on leads, contacts, opportunities and custom activities. When you create a lead through the API, you can nest contacts and custom fields in the same request.

That model is built for company-first selling, and LinkedIn data is person-first. Pick one pattern and apply it everywhere:

Pattern How it works Good for Risk
Company lead + nested contact Create or find the company lead, add the person as a contact Multi-threading, account-based selling Needs a company name or domain from the LinkedIn data
Person-named lead Lead named after the person, one contact Solo founders, SMB, very small accounts Splits one company into many leads

Matching Before You Create

This is where most syncs go wrong. A LinkedIn tool will happily send a "reply received" event for someone Close already knows from cold email, and a naive flow creates a second lead.

  1. Store a normalised LinkedIn URL in a custom field on the contact. Strip tracking parameters and trailing slashes, and lowercase it, so the same profile always produces the same string.
  2. Search Close first. Close documents an advanced filtering API for finding leads or contacts by criteria. Search by LinkedIn URL, then by email.
  3. Create only on a miss, and write the URL on creation so the next event matches.
  4. Guard against repeat events. Webhooks can arrive more than once (directional), so store an event or message identifier and skip ones you have already logged.
  5. Clean up with merge. Close has a merge-leads endpoint for the duplicates that slip through.
We did not find Close documentation on automatic duplicate handling when creating leads through the API, so we treat matching as your job. If you have confirmed behaviour in your own account, build on that, but test it with a duplicate first.

Keep a single custom field such as "LinkedIn status" so reps can build a Smart View of replied prospects. Rate limits matter if you sync in bulk: Close applies limits per endpoint group, returns a RateLimit header, and expects you to wait for the reset value after a 429 response. Frequently Asked Questions

Does HeyReach integrate natively with Close CRM?

We found no native HeyReach-built Close integration. We could not open HeyReach's CRM integrations article, so treat this as "none found" rather than a vendor-confirmed "none exists". The routes we found are OutboundSync (a third-party beta), Zapier, and HeyReach webhooks into a flow you build.

Can I sync LinkedIn replies into Close?

Yes. OutboundSync lists messages and replies among the events it logs as Close lead activity. With webhooks, HeyReach's "Every Message Reply Received" event can trigger a flow that writes a note on the matching Close lead.

How do I avoid duplicate leads in Close from LinkedIn campaigns?

Search before you create. Match on a normalised LinkedIn profile URL stored in a custom field, with email as a second key, and only create a lead when nothing matches. We did not find Close documentation describing automatic duplicate handling on lead creation (directional), so do not rely on it. Close has a merge-leads endpoint for cleanup.

Should a LinkedIn prospect be a Close lead or a contact?

In Close, a lead represents a company and contacts sit under it. Decide once: create a company lead with the prospect as a nested contact, or attach the contact to an existing company lead. Mixing both is the usual source of messy data.

Do I need a paid HeyReach plan for the Close sync?

OutboundSync states that webhooks and the API are included on all HeyReach plans, so the sync works on any of them. Plan terms change, so confirm in your own account before you buy.

Is the sync two-way?

OutboundSync is one-way, HeyReach to Close, and labels the pairing beta. Sending Close changes back to HeyReach, such as adding a lead to a campaign when a Close status changes, needs a separate Zapier or webhook flow.
